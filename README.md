Проект по финальному заданию (анализ данных, регрессионные модели, сравнение метрик и создание признаков) научил меня:

Применять ML-методы в реальных задачах — привёл 5 примеров из жизни (прогнозирование цен на недвижимость, рекомендательные системы, обнаружение мошенничества, диагностика заболеваний, предсказание оттока клиентов) и объяснил пользу каждого.

Классифицировать задачи — отличать supervised/unsupervised, регрессию от классификации, бинарную от мультиклассовой, а также понимать разницу между multiclass (один класс из многих) и multilabel (несколько меток одновременно).

Понимать связь регрессии и классификации — задача с ценами на дома — это регрессия (непрерывная целевая переменная), но её можно свести к классификации, например, разбив цены на категории (низкая/средняя/высокая).

Проводить первичный анализ данных (EDA) — загружать данные из Kaggle (JSON), определять размер датасета, список колонок, целевую переменную, использовать info(), describe(), corr() для поиска пустых значений и понимания распределений.

Анализировать целевую переменную — строить гистограмму и boxplot, выявлять выбросы, отсекать хвосты по 1 и 99 перцентилям, объяснять изменения распределения после фильтрации.

Анализировать категориальные признаки — определять тип (interest_level), смотреть частоты, кодировать их в числа (0,1,2) для использования в моделях.

Исследовать корреляции — строить тепловую карту и scatterplot'ы, делать выводы о наличии/отсутствии линейной связи между признаками и ценой.

Создавать новые признаки — квадраты признаков, полиномиальные признаки степени 10 с помощью PolynomialFeatures, оценивать их влияние на корреляцию с целевой переменной.

Разбивать данные на train/test — готовить выборки для обучения и валидации.

Обучать модели регрессии — линейную регрессию, дерево решений, наивные модели (среднее и медиана). Сравнивать их качество по метрикам MAE и RMSE.

Оценивать модели — понимать, что MAE менее чувствителен к выбросам, чем RMSE; сравнивать результаты на train и test для выявления переобучения.

Формировать итоговую таблицу метрик — видеть, какая модель даёт наименьшую ошибку (в данном случае, скорее всего, дерево решений или линейная регрессия после полиномиальных признаков).

Практиковаться с полным набором данных — пробовать создавать больше признаков, чтобы улучшить качество предсказаний.

В итоге я закрепил полный цикл работы над регрессионной задачей: от загрузки и очистки данных до обучения моделей, оценки их качества и интерпретации результатов. Это важный этап перед более сложными проектами в области прогнозирования.
